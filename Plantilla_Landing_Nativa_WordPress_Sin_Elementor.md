## 1. Diagnóstico exacto: ¿por qué se rompió la versión anterior?

Al inspeccionar el código fuente compilado en vivo (`autoptimize_eef2af0...css`) y tu captura del administrador (`post=17618`), aparecieron **3 causas técnicas exactas**:

1. **Editor Clásico (`wpautop`) rompió el `<style>`:** Tu WordPress usa el **Editor Clásico** (pestañas `Visual` / `Código`), no Gutenberg. Al pegar CSS con saltos de línea, WordPress inyectó `<p>` y `<br />` dentro de cada línea de CSS (`:root{<br/> --ism-navy:#0a2540;<br/>}</p>`), invalidando el 100% de los estilos al pasar por Autoptimize.
2. **Doble cabecera con el tema Vault:** La plantilla cargó el menú transparente global de Vault (`#wrapper-navbar.uicore-transparent`) encima del contenido.
3. **SVG con `lazyload` sin dimensiones fijas:** El plugin de lazy-load expandió el logo SVG al ancho completo al perderse el CSS.

> [!IMPORTANT]
> **Cómo está blindada esta v2:**
> Todo el bloque (`<style>` + HTML + `[contact-form-7 id="16782"]` + `<script>`) va **compactado en una sola línea sin saltos de línea (`0` saltos)**. Así `wpautop` del Editor Clásico **no puede inyectar ni un solo `<br />` ni `<p>`**, Autoptimize procesa el CSS limpio, se oculta automáticamente el header/footer de Vault solo en esta landing para evitar fugas, y se usan **7 fotografías reales de los talleres del ISM** ya alojadas en `ismchile.cl`.
